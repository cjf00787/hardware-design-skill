# hardware-design — 从想法到《原理图&PCB绘制说明》

文档驱动的硬件设计工作流：AI 负责调研、方案、选型核算、撰写设计文档、绘制 SVG 拓扑图；**原理图与 PCB 的绘制永远由用户在 EDA 软件中完成**。适用于分立元件 + 芯片的中小规模板卡设计。

## 总则（红线）

1. **文档驱动**：不操作 EDA、不布线、不代替用户画图。AI 的产物是：调研、方案、选型表、设计文档、SVG 拓扑图、审查报告。
2. **禁止猜——所有结论必须有据**，三类证据之一：
   - 芯片手册页码/章节（设计文档中标注"（XX 手册 p.xx）"）
   - 实测值（注明测量条件）
   - 写出过程的计算（公式 + 代入数值）

   "应该是 / 大概 / 一般来说"不是结论。找不到依据 → 标"待确认"，问用户或联网核实，核实前不写进设计。
3. **不确定直接问用户**。判断标准：任何两个不同答案会导出不同电路的问题，都必须问。
4. **中间产物单独存放**：本项目生成的脚本放 `scripts/`，规格书放 `datasheets/`，文档放 `docs/specs/`，不散落项目根目录。
5. **审查只由用户发起**：交付设计文档时提议一次审查入口（见阶段 4），之后不催促、不主动执行。
6. **视觉材料需要视觉能力**：截图/照片类输入只有具备视觉能力的模型才能处理。无视觉能力时**不得假装看图**，改走文本替代：请用户从商城网页复制引脚表文本、从 EDA 导出符号/网表/坐标文本，或提示用户换用有视觉能力的会话再发图。

**借口拦截表**：

| 借口 | 现实 |
| --- | --- |
| "这个参数我记得到" | 记忆不可作依据。查手册，标页码 |
| "中文站资料写着呢" | dzsc/维库等站有大量 AI 生成规格书，参数常错标。只作线索，写进设计必须原厂 PDF |
| "用户应该不介意我直接定" | 每个方案分叉点都要用户拍板（G1/G2/G3） |
| "引脚看 EDA 库就行了" | EDA 库（尤其嘉立创在线库）引脚可能与手册不同，以手册为准核对 |
| "先写完文档再补依据" | 无依据的段落就是错的段落，逐段带证据写 |

## 阶段 0 · 环境与产物组织

1. 检查 `python --version`。skill 自带脚本（`scripts/`）仅用标准库，通常无需安装任何包。项目需要而环境中缺失的工具：向用户说明来源与安装位置，征得同意后再安装。
2. 在项目内建立工作区（已存在则复用）：

   ```text
   docs/specs/          设计文档
   docs/specs/images/   SVG 拓扑图
   scripts/             本项目的中间脚本（复制 skill 自带脚本或新写）
   datasheets/          规格书 PDF（可按用户习惯改名）
   ```

3. 不在计划模式 → 请用户切到计划模式再开始构思；方案经 G1 确认前不落盘任何设计内容。

## 阶段 1 · 全网方案搜寻与构思 → G1

1. 问清需求：用途、关键指标（电压/电流/精度/接口/体积/预算）、**用哪个 EDA 软件、打算在哪家板厂打样**。任何两个答案会导出不同电路的问题都必须问。
2. **全网搜寻参考方案，不限于固定网站**：GitHub、嘉立创开源广场（oshwhub.com）、芯片原厂参考设计、Hackaday/EEVblog、技术博客与论坛。按项目类型定制关键词，中英各搜一轮。汇总对比表：方案 | 核心器件 | 优缺点 | 来源链接。
3. 与用户逐项确认细节 → 产出一页《设计方案》：系统架构、关键器件候选（2~3 个备选 + 理由）、功率/接口预算、风险点。
4. **G1：用户确认方案后才进入阶段 2。**

## 阶段 2 · 选型与规格书 → G2

1. 先出《选型指标表》：每类元件的耐压/耐流/精度/封装要求，只有指标不含型号。方法见 `references/selection-checklist.md`。
2. 问分工：用户自己选型，或 AI 查（AI 优先立创商城 szlcsc.com；国际用户 LCSC/DigiKey/Mouser）。
3. 问手册来源：用户下载放 `datasheets/`，或 AI 下载。文件命名 `型号_厂商_版本.pdf`。
4. **逐颗核对手册**（加载 `references/datasheet-workflow.md`）：
   - 同型号不同厂参数/封装可能不同（如 SS56 各家 Ir/Vf/封装不同）——以实际购买渠道厂商的手册为准
   - 每颗的核对结论回填选型表，并标注手册页码
5. **引脚确认**：EDA 库符号引脚可能与手册不同（嘉立创 EDA 在线库尤甚）。请用户提供 EDA 库引脚图（截图）或导出符号信息，与手册引脚定义逐脚对照；差异以手册为准，提醒用户修库或换库。无视觉能力时走总则 6 的文本替代（商城商品页引脚表可复制文本、多数 EDA 支持导出符号定义）。
6. **G2：选型 + 引脚双确认后才写文档。**

## 阶段 3 · 写设计文档 → G3

1. 加载 `references/design-doc-template.md` + `references/svg-diagram-guide.md`；涉及 PCB 章节时加载 `references/pcb-guidance.md`——**先确认用户的板厂，联网查该厂当期工艺参数（叠层/铜厚/PP 介电常数/阻抗工具），查到的数值记入文档并注明来源与查询日期，禁止套用过期或别家板厂的数值**。
2. 文档结构（模板含完整骨架与写作要求）：
   - 方案简介：指标表 + 系统架构 SVG + 热/功耗预算
   - 原理图结构说明：每模块 = 一句功能 + 拓扑 SVG + IC/连接器引脚接法表 + 本模块元器件表 + **表下选型计算** + 注意事项
   - PCB 结构设计：板材/叠层/阻抗/布局/布线规则
   - 固件要点（编号列表）
   - BOM：全元件、无价格
   - **不写"待办"章节**——遗留事项并入对应模块的注意事项，已成定局的写成定案
3. 硬规则：
   - 位号全板唯一，任何位号只出现在一个模块的元器件表里
   - 表格必须足以让用户照着画出原理图（位号 + 参数 + 封装 + 连接全备），跨模块只用网络名
   - 关键参数标注出处；拓扑图按 `references/svg-diagram-guide.md` 风格绘制
4. 自查：运行项目 `scripts/` 内的位号检查脚本（阶段 0 已从 skill 复制）：`python scripts/verify_designators.py <设计文档路径>`，位号重复与 BOM 不一致清零；再过一遍模板末尾的人工核对清单。
5. **G3：交用户验收**，并提议阶段 4 的两个可选审查。

## 阶段 4 · 可选审查（用户发起）

仅在用户提供文件时执行；方法见 `references/review-workflow.md`。

- **原理图网表审查**：用户画完原理图后从 EDA 导出网表（文本格式）→ 重建网络连接，与设计文档的元器件表/引脚接法表逐项对照 → 差异清单（附网表原文 vs 文档原文）。
- **PCB 布局审查**：用户布局完成后导出器件布局/坐标 → 对照设计文档 PCB 章节的布局分区/间距/布线规则核对 → 差异清单。

审查发现的问题由用户在 EDA/文档中修改，AI 不改 EDA 文件。用户发来的是截图而非导出文件时：处理截图需要视觉能力，无视觉能力则请用户改发文本导出（网表/坐标 CSV）或换有视觉的会话（总则 6）。

## 常见错误

- 位号在两个模块表重复 → 用户画图时无所适从。唯一化。
- BOM 与模块表对不上 → 采购漏买。交稿前跑 `verify_designators.py`。
- 参数无出处 → 无法复核，等于没写。
- 板厂参数张冠李戴 → 阻抗与线宽全错。运行时查当期参数，注明来源与日期。
- 把"待办"写进文档 → 文档是定案快照，不是任务清单。
- 固件章节混入硬件接法 → 接法属于原理图模块表，固件只写行为与时序。
